# 语体：精简

在 `base.md` 之上用。本文件只列放宽了哪些条、额外要做什么；没列到的照 `base.md`。

## 适用

- 用在：用户明说要"简洁""精简""要点""速查""一页纸"，或文档只给作者本人看。周报、纪要等文档本身不触发，用户明说时才用。
- 不适用：
  - 面向公众，或影响读者的权利、钱款、安全 → 只按 `base.md` 写，在交付说明里告诉用户为什么不精简。
  - 读者阅读有困难 → `easy-read.md`。

## 放宽 `base.md` 的条目

| `base.md` 的规则 | 精简时 |
| --- | --- |
| 交付说明写读者、读完要做的事、阅读情境 | 写一行：读者和用途 |
| 用"你"称呼读者 | 不称呼读者 |
| 标题写成陈述句或问题 | 可以用名词短语，如"TCP 三次握手" |
| 每段首句是要点，一段不超过 6 句 | 以列表和表格为主，不写成段落 |
| 一句一个动作或事实，写出主语 | 一条一个意思；主语明确时可以省略，可以用短语 |
| 术语首次出现时定义，缩写首次写全称 | 只定义读者没学过的；读者熟悉的术语和缩写直接用 |
| 列举不以"等"收尾 | 不影响使用时可以用"等" |
| 正文不用"/"表示"或" | 表格和列表里可以用"/"，句子里仍写"或" |

下列规则不放宽：事实能在原始材料里找到、缺的写 `【待补：缺什么】`；一词一义；受控情态词；警告的写法；标点、数字与单位。

## 写作规则

- 删掉过渡句、背景铺垫、"综上所述"式重复总结，以及作者自己的工作经过。
- 每条先写结论、定义、数字或公式，理由紧跟在后，压到半句以内。
- 两个以上容易混淆的概念，用对比表写：每行一个概念，每列一个比较维度。
- 推导或因果链用"→"连接："缓存未命中 → 回源 → 延迟升高"。
- 例子只在不看例子会误解时给，每条最多一个。
- 用户给了篇幅或条数时按用户的；没给时，同一层列表不超过 7 条，超出时分组加小标题。
- 原文里的操作过程照 `blocks/steps.md` 写，不压缩成一句。

## 审查清单

- [ ] 没有过渡句、背景铺垫、重复总结。
- [ ] 每条以结论、定义、数字或公式开头。
- [ ] 易混概念写成了对比表。
- [ ] 同一层列表不超过 7 条，或用户另给了条数。
- [ ] 定义了的术语都是读者没学过的。
- [ ] 不放宽的那几条仍然逐条通过了 `base.md` 的审查清单。

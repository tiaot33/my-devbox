# API 参考、SDK 文档

## 适用

- 读者：懂编程基础的开发者，来查某个类、方法、端点、字段或命令的确切行为，常把示例代码直接复制进自己的项目。
- 用在：类库和 SDK 的参考页、源码里的文档注释（Javadoc、docstring 等）、proto 注释、OpenAPI 描述文件里的 `summary`、`description` 和示例、REST 端点参考页、命令行工具的命令和选项参考，以及代码改动后的参考文档更新。
- 不适用：从零教会读者用某个 API、按步骤完成任务 → `tutorial.md`
- 不适用：项目首页上的简介、安装和快速用法 → `readme.md`
- 不适用：接口设计的取舍、内部模块间的接口规格 → `design.md`
- 不适用：面向最终用户的产品使用说明 → `user-manual.md`
- 不适用：软件版本说明 → `lifecycle-other.md`；CHANGELOG 尚无专门规则，只按 `base.md` 写，并在交付说明里告诉用户。

## 必需章节

每个程序元素（类、方法、属性、端点、命令）一篇或一个条目。整套参考用同一套章节顺序和标题写法。标了"可选"的章节，条件不满足时整节省略；没标"可选"的章节，每篇都写。章节名用下面的固定名称，这是对 base"标题写成陈述句或问题"的例外。

1. **标题**：元素名加元素类型，如"`Clear` 方法"。多个元素同名时加区分词（父元素名或产品名），如"`Device.Clear` 方法""`Clear` 方法（ADO）"。REST 端点写 HTTP 方法加路径模板，括注操作名，如"`POST /v2/projects/{project_id}/tasks`（创建任务）"。
2. **描述**：一两句，说明元素做什么或代表什么，不重复元素名。写法见"写作规则 · 描述"。
3. **声明或语法**：定义元素的代码签名。元素可以用多种语言调用时，每种语言各给一份。REST 端点写 HTTP 方法和路径模板；命令写语法格式。
4. **参数**（可选：元素有参数时）：每个参数写名称、数据类型、必需还是可选、说明，适用时写输入还是输出。REST 端点另写位置（path、query、querystring、header、cookie；querystring 只在 OAS 3.2 及以后有）。请求体字段也按参数写，位置写"请求体"，嵌套字段写完整路径，如 `due.date`。参考页里用"名称、位置、类型、必需、说明"表格，整套参考列法一致。
5. **返回值**（可选：元素有返回值时）：返回什么、数据类型。REST 端点写成功响应和每个已知错误响应；响应体字段用"字段、类型、说明"表格。
6. **异常或错误**（可选：元素会抛异常或返回错误时）：逐个列出，每个写发生条件。
7. **属性值**（可选：属性或字段）：数据类型和默认值。
8. **备注**（可选：签名、参数、返回值看不出的行为）：与相近元素的区别、常见陷阱，以及放不进描述的行为说明。
9. **权限**（可选：调用需要权限时）：所需权限，以及缺少权限时的行为。认证方式写在总览页，这里只链接过去。
10. **示例**：演示用法的代码，写法见"写作规则 · 代码示例"。常量和字段的条目不写。类、接口页面另在描述之后放一段 5～20 行的概览示例；其余示例放在本节。
11. **要求或适用范围**（可选：有语言或平台要求时）：写明要求。
12. **弃用说明**（可选：整个元素已弃用时）：写法见"写作规则 · 弃用"。
13. **另请参阅**：相关元素和延伸资料的链接。

## 写作规则

### 取规则的顺序

- 先用项目自有风格，其次用项目选定的主指南（Google 或 Microsoft），主指南没有规定的再查另一本。项目没有选定时，以 Google 为主指南。

### 覆盖面

- 每个公开的类、接口、结构体、常量、字段、枚举、typedef 和方法都写描述；方法逐个写每个参数、返回值和会抛出的每个异常。描述再短也不省略，因为很多工具读取这些注释。
- 参考由源码注释自动生成时，生成后通读一遍：补上读者需要而开发者没写的细节，删掉实现细节和内部信息。
- 内部说明（TODO、FIXME、非公开链接）放进生成器不导出的注释格式里；proto 用 `(--` 和 `--)` 包起来。
- REST API 的基础 URL、认证方式、通用错误格式写进一页总览，端点页链接过去，不在每页重复。OpenAPI 里对应写在顶层的 `servers`、`security` 和 `components`。

### 描述

- 让第一句单独也能读懂，因为生成器会把它抽进类列表、摘要和索引。第一句只写从元素名和签名看不出的信息。第一句里不用带句点的缩写，生成器会在第一个句点处截断。
- 方法描述以下表的动词开头，主语默认是该方法，不加"请""你""你可以""用于""此方法"。这是对 base"写出动作的执行者"的例外，只用于元素描述。
- 方法描述、REST 端点描述和 OpenAPI Operation 的 `summary` 都按下表选开头：

| 方法类型 | 中文开头 | 英文开头 |
| --- | --- | --- |
| 执行操作并返回数据 | 描述该操作的动词，如"搜索……""创建……" | 描述该操作的动词，如 "Searches …" |
| 返回布尔值的 getter | "检查是否……" | "Checks whether …" |
| 返回其他值的 getter | "获取……" | "Gets the …" |
| 无返回值 | "设置……""更新……""删除……""注册……" | "Sets …" "Updates …" "Deletes …" "Registers …" |
| 回调 | "在……时由……调用。"后文写"子类实现此方法以……" | "Called by … when …"，后文写 "Subclasses implement this method to …" |
| 构造对象的便利方法 | "创建……" | "Creates a …" |

- 类的描述第一句写用途，后文写怎么实例化或获取、关键特性、最佳实践和陷阱。
- 常量和字段的描述写到最短，链接到使用它的方法。
- 逐项回答下列问题，答案写进描述、备注或权限章节：成功和失败时各做什么、是否幂等、有什么副作用、单位是什么、常见错误有哪些、需要哪些权限或初始化、缺少时怎样。缺少依赖的写法如"缺少该权限时抛出 `SecurityException`"。
- 跳过编程基础概念的解释，篇幅留给本产品特有的行为。

### 参数和返回值

- 非布尔参数用名词短语写它是什么，如"要获取的用户的 ID。"
- 让 API 执行某动作的布尔参数，分别写 true 和 false 时的行为；描述现有状态的布尔参数，写"如果……，则为 true；否则为 false。"
- 写出参数名和类型之外的信息：输入格式、取值范围和边界值是否包含、字符串的最短和最长长度及允许的字符。还要写超长时截断还是报错、省略或为空时怎样。
- 参数有默认行为时，先写每个取值或取值范围对应的行为，再用"默认值：……"写默认值。
- 返回值写短，详细说明放到类描述里；非布尔返回值用名词短语，如"由给定 ID 指定的用户。"；布尔返回值写成立的条件。
- 返回值因实现方或配置而异时，写明差异。

### 异常和错误

- 每个异常或错误写"名称：发生条件"，如"`IOException`：发生 I/O 错误。"
- 在生成器会自动加"Throws"的语言里，异常说明以"如果……"开头，如"如果未分配密钥。"
- REST 端点的状态码从 IANA 状态码注册表中选。
- API 在响应体里返回错误码时，用一张表列出每个错误码，列为状态码、错误码、发生条件、调用方怎么处理。
- 同一错误码只对应一种错误；发现一码多义时，写 `【待补：请开发者确认错误码含义】`。
- HTTP 层的码叫"状态码"，响应体里的码叫"错误码"，两者不混称。状态码的数字和名称都用代码字体，如"HTTP `400 Bad Request` 状态码"。
- 正文里状态码范围写 `2xx`、`4xx`；OpenAPI 文件里的范围键按 OAS 写大写的 `4XX`。

### 弃用

- 弃用说明的第一句写"已弃用。"和替代项，如"已弃用。请改用 `CameraPose`。"；没有替代项时，第一句写"已弃用，没有替代项。"。后续句子写弃用原因。摘要和索引只显示第一句。
- 只有参数、字段或取值弃用时，在该参数说明的开头写"已弃用。"和替代项，不单设"弃用说明"节。
- API 有版本号时，写首次弃用的版本。
- 方法弃用时，写出调用方怎么改代码才能继续工作。
- OpenAPI 里给弃用的操作、参数、响应头设 `deprecated: true`；proto 里设 `deprecated` 选项为 true，注释第一行以 "Deprecated: " 开头。

### 代码示例

- 优先给常用元素和难用元素写示例；先写最简单的常见场景，再逐步加复杂度；复杂的多步场景链接到教程。
- 示例前写一段引导：示例演示什么场景、代码里看不出的要点、运行所需的依赖和环境。引导语紧挨示例时以冒号结尾。
- 写出预期输出，放在示例后单独一段，或写在代码注释里。
- 交付前编译并运行每个示例；没有运行条件时，在示例后写 `【待补：编译并运行此示例，核对输出】`。
- 示例按安全写法写：校验用户输入，密钥和密码用占位符，不写真实值。
- 占位符用描述性名称，全大写加下划线（`API_KEY`），不加 `MY_`、`YOUR_` 前缀，全文只用一种写法。
- 主指南是 Microsoft 时，占位符用尖括号（`<api-key>`）；shell 命令里尖括号是重定向符，命令示例仍用全大写写法。
- 在示例后逐个说明占位符：一个时写"把 `API_KEY` 替换为……"；多个时用"替换以下内容："引出列表，按出现顺序排列。
- 省略的代码用该语言的注释标出，如 `# 此处省略连接配置。`，不用 `...` 或省略号；含省略的代码块不提供一键复制。JSON 这类没有注释语法的格式不省略，写一个最小的完整值，如只含一个元素的数组。
- 一键复制的代码和命令，复制后只替换占位符就能运行。里面不放作语法记号的 `[]`（可选）、`{}` 和 `|`（必选其一）、`...`（可重复），语法格式写在"声明或语法"一节；代码本身的 JSON、数组、管道照写。
- 路径模板里的 `{project_id}` 在可复制的命令里换成占位符 `PROJECT_ID`。
- 只在异常处理本身是示例要演示的内容时写异常处理；不捕获因参数非法而抛出的异常。
- 示例每行不超过 80 个字符；更长的命令在合适的字符前断行，续行缩进四个空格。

### 代码入文

- HTTP 方法、状态码、数据类型、环境变量也用代码字体，base 只要求代码标识符、命令和路径。
- 文档注释里的代码字体用该注释格式的标记：传统 Javadoc（`/** */`）用 `{@code ...}`；JDK 23 起的 `///` Markdown 注释、proto 和 OpenAPI 的 CommonMark 用单反引号；reST 风格的 docstring 用双反引号。
- 每节第一次出现的 API 元素链接到它的参考页，同节后面只用代码字体。
- 代码元素后面接类别名词，如"`Intent` 对象"；不把代码元素当动词用，写"发送 `POST` 请求"，不写"`POST` 数据"。
- 提到方法时省略类名，如"调用它的 `get` 方法"，有歧义时才写类名。
- 字符串字面量用代码字体并带双引号，如 `"auto"`。

### OpenAPI 描述文件

- 动笔前确认目标 OAS 版本（`openapi` 字段）和工具链支持的版本，按该版本的必填项写。工具链是否支持 3.2 查不到时，写 `【待补：确认工具链支持的 OAS 版本】`。
- 按 3.1 写时每个 Response 都写 `description`（3.1 必填，3.2 改为可选）。下列字段只在 3.2 及以后使用：`dataValue`、`serializedValue`、Response 的 `summary`、Tag 的 `summary`、`parent` 和 `kind`、参数的 `in: "querystring"`。
- Operation 的 `summary` 写一句操作做什么，`description` 写详细行为；Path Item 上的 `summary`、`description` 只写对该路径下所有操作都成立的内容。
- `operationId` 在全部操作中唯一。
- `info.version` 写描述文档自己的版本，不等于 `openapi` 字段的 OAS 版本，也不等于 API 实现的版本。
- path 参数写 `required: true`；请求体需要时显式写 `required: true`（默认是 false）。
- 示例值与对应 schema 兼容。Schema 里用 `examples` 数组；只有需要兼容 OAS 3.0 及更早版本时才用 `example`。
- 同一个 Parameter、Header 或 Media Type 对象里，`example` 和 `examples` 只写一个。
- `description` 里只用 CommonMark 基本语法；扩展语法在不同工具里渲染结果不一致。
- 链接写带协议的绝对 URL；相对链接会按渲染位置解析，可能指错地方。

### proto 注释

- service、method、message、field、enum、enum value 都写注释，注释放在组件前面。
- service 的注释写服务是什么、用户能用它做什么。
- 注释里用 CommonMark，不用标题、表格、原始 HTML 和 ASCII 图；需要图时链接到含图片的文档页。
- 交叉引用用 Markdown 引用链接，写全限定名或作用域内的相对名。

### 代码改动后同步

- 把参考文档更新算进代码改动的完成标准：同一次改动里更新受影响元素的签名、参数、返回值、错误、默认值和示例。同步后按"代码示例"一节重新运行受影响的示例；被替代的旧元素按"弃用"一节写说明。
- 在仓库文档里搜索改动元素的名称，把仍用旧用法的 README、教程和其他参考页列进交付说明。
- 从代码推不出的行为（幂等性、副作用、错误条件、权限）请改动的开发者核对；未核对的写 `【待补：请开发者确认……】`。

### 英文文档

- 方法描述以第三人称单数动词开头："Creates a new task on the specified task list."，不写 "Create a new task …"。句式见"描述"一节的表。
- 参数说明首字母大写、句号结尾；非布尔参数以 "The" 或 "A" 开头；描述状态的布尔参数写 "True if …; false otherwise."，这里的 true、false 不用代码字体也不加引号；默认值用 "Default:"。
- 非布尔返回值以 "The …" 开头。异常说明在会自动加 "Throws" 的语言里以 "If …" 开头，否则以 "Thrown when …" 开头。
- 弃用写 "Deprecated. Use `X` instead."。
- 类名不加复数和所有格，在后面加名词再变形："`Intent` objects"，不写 "`Intent`s"。
- 指 HTTP 状态码时写 "status code"，不写 "response code" 或 "error code"。
- 正文引用已有的错误消息时加引号，消息文字保持原样；本项目新写的错误消息用句子式大小写。
- 用字面意思写，比喻和典故换成直接说法，因为很多读者的母语不是英语。

## 审查清单

- [ ] 每个公开元素（类、接口、结构体、常量、字段、枚举、typedef、方法）都有描述；只改单页时，只核本页涉及的元素。
- [ ] 每个方法的每个参数、返回值和会抛出的每个异常都有说明。
- [ ] 每篇的标题是"元素名 + 元素类型"，同名元素带区分词；REST 端点标题是 HTTP 方法加路径模板。
- [ ] 章节顺序和标题写法与仓库里已有的参考页一致；没有已有页时标不适用。
- [ ] 没标"可选"的章节每篇都有。
- [ ] 每个描述的第一句不以"它""此""该"指向上文，没有重复元素名，句中没有带句点的缩写。
- [ ] 方法和端点描述以句式表里的动词开头，不含"请""你""用于""此方法"。
- [ ] 每个参数都写了类型和必需还是可选；REST 参数还写了位置。
- [ ] 字符串和数值参数写了格式、范围或长度，ID 类参数除外。
- [ ] 有默认行为的参数都写了"默认值："。
- [ ] 布尔参数写了 true 和 false 各自的行为，或写成"如果……，则为 true；否则为 false。"
- [ ] 需要权限或其他依赖的元素，写了依赖和缺少依赖时的行为。
- [ ] 有副作用或重试风险的操作写了是否幂等。
- [ ] 每个异常或错误都写了发生条件。
- [ ] REST 端点列出了成功响应和每个已知错误响应，状态码都在 IANA 注册表中。
- [ ] 返回错误码的接口有错误码表，每行都有发生条件和处理方式。
- [ ] 每个弃用元素的第一句写了"已弃用"和替代项，或写了没有替代项；后续句子写了原因。
- [ ] API 有版本号时，弃用说明写了首次弃用的版本。
- [ ] 被新元素替代的公开元素都加了弃用说明。
- [ ] 类、接口页面的描述后有一段 5～20 行的概览示例。
- [ ] 每个示例前有引导，写了场景和运行依赖。
- [ ] 每个示例都写了预期输出。
- [ ] 每个示例都已编译运行，或留有运行核对的 `【待补】`。
- [ ] 不以演示异常处理为目的的示例，没有捕获参数非法的异常。
- [ ] 示例里没有真实的密钥、密码或令牌。
- [ ] 每个占位符都有说明，全文只用一种占位符写法，命令里没有尖括号占位符。
- [ ] 省略的代码用语言注释标出，含省略的代码块没有一键复制；JSON 里没有 `...`。
- [ ] 一键复制的代码和命令里没有作语法记号的 `[]`、`{}`、`|`、`...`，路径模板已换成占位符。
- [ ] 正文里的 HTTP 方法、状态码、数据类型、环境变量都用代码字体。
- [ ] 文档注释里的代码字体用的是该注释格式的标记，如传统 Javadoc 里是 `{@code}`。
- [ ] 每节第一次出现的 API 元素链接到参考页。
- [ ] 生成的参考里没有 TODO、FIXME、内部链接、私有成员名和内部类名。
- [ ] OpenAPI：`openapi` 字段的版本与工具链支持的版本一致，或留有确认工具链的 `【待补】`；没有用该版本之外的字段，满足该版本的必填项。
- [ ] OpenAPI：`operationId` 全部唯一，path 参数都是 `required: true`。
- [ ] OpenAPI：示例值与 schema 兼容，Schema 里没有用已弃用的 `example`（需兼容 3.0 的除外）。

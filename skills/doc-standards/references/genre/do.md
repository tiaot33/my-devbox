# 用途：照做

## 判定

- 读者读完要按顺序操作，完成一件具体的事。
- 典型文档：SOP、部署或发布步骤、环境搭建说明、值班处置手册、操作检查单。
- 容易混淆：
  - 学会一项软件技能的教程、软件操作指南 → `tutorial.md`。
  - 实体产品的使用说明 → `user-manual.md`。
  - 读者只是来查某一步怎么做 → 仍按本用途写，加目录让读者跳到对应过程。

## 结构

1. **标题**：写读者要完成的事，动词开头："回滚生产数据库"。
2. **结果**：一两句写做完以后得到什么、大约要多久。
3. **前置条件**：权限、工具及版本、要事先准备的数据；列在第一步之前。
4. **过程**：一个任务一个过程；任务有几个阶段时，每个阶段一个小标题。
5. **确认结果**：读者怎样判断已经成功。
6. **出错时**（可选：已知有常见失败时）：现象 → 原因 → 处置。

## 写作规则

- 一份文档只完成一个任务；多个任务拆成多份，或在开头列出任务清单分节写。
- 不可逆或有风险的操作，前一步写明后果和回退办法，按 `base.md` 的警告写法写。
- 原理、背景只留一句话，其余链接到解释性文档。
- 读者在压力下读（如值班处置）时，每个过程放进一屏，先写最常见的情况。

## 要读的内容块

- `blocks/steps.md`：必读。

## 审查清单

- [ ] 标题以动词开头，写的是读者要完成的事。
- [ ] 前置条件在第一步之前。
- [ ] 结尾写了怎样确认成功。
- [ ] 每个不可逆操作之前都写了后果和回退办法。
- [ ] 原理和背景每处不超过一句。

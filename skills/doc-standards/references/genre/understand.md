# 用途：理解

## 判定

- 读者第一次弄懂一个概念、系统、原因或思路，读完能自己讲出来或做出判断。
- 典型文档：原理讲解、技术博客、设计思路介绍、新人入职介绍、学习讲义、事故原因解释。
- 容易混淆：
  - 面向公众的科普 → `popular-science.md`。
  - 架构描述、设计说明 → `architecture.md`、`design.md`。
  - 读者已经懂，回来查 → `genre/lookup.md`。

## 结构

1. **标题**：写读者会弄懂什么，可以写成问题："为什么 Redis 单线程还这么快"。
2. **一段话答案**：开头用三五句写出结论。只读这段的读者也拿到了要点。
3. **展开**：按读者理解的顺序，从读者已知的东西讲到新东西；每节回答一个子问题。
4. **边界**：这个结论在什么条件下不成立、常见误解是什么。
5. **延伸**（可选）：下一步读什么，写出每个链接能解决什么问题。

## 写作规则

- 先给一个具体例子或场景，再给抽象定义。
- 每引入一个新概念，说明它和前面已讲概念的关系。
- 类比只用来引入，类比失效的地方要写明。
- 给出判断时写出依据；作者自己的观点标明是观点。

## 要读的内容块

- `blocks/figure-table.md`：有示意图、对比时读。
- `blocks/citation.md`：引用了外部事实或观点时读。

## 审查清单

- [ ] 开头一段写出了结论。
- [ ] 每个新概念出现前，读者需要的前置概念已经讲过或给了链接。
- [ ] 写了结论不成立的条件或常见误解。
- [ ] 每个类比都写明了失效的地方。

# 用途：查阅

## 判定

- 读者已经懂这个主题，回来查某一点或快速回忆，不从头读。
- 典型文档：复习笔记、读书笔记、速查表、FAQ、配置项清单、命令清单、知识卡片、团队术语表。
- 给自己整理的笔记默认按本用途写；用户说要写成讲义、给别人第一次学时，按 `genre/understand.md` 写。
- 容易混淆：
  - 读者第一次学这个主题 → `genre/understand.md`。
  - API、SDK 的参考文档 → `api-reference.md`。

## 结构

1. **标题**：写主题和范围："Go 并发原语速查""计网第 3 章复习"。
2. **目录**（可选：二级标题超过 5 个时）。
3. **条目**：按读者查找的方式分组，如按主题、按字母序、按使用频率；组内每条结构相同。
4. **易混对比**（可选：有容易混淆的概念时）：对比表。

## 写作规则

- 每条自成一体：只读这一条也能看懂，不依赖"如上所述"。
- 同组条目用同一结构，如"名称 → 定义 → 关键点 → 例子"，全组统一。某一项对这个条目不适用时写"—"；该有但材料没给时写 `【待补：缺什么】`。
- 不写"按知识点分组""每组一张表"这类描述文档本身的话。
- 条目名用读者查找时会想到的词，读者常用的别名在条目里写出。
- 复习类笔记把定义、公式、结论、典型考点放在前面，推导放在后面或折叠起来。
- 和其他条目有关的，写出条目名链接过去，不重复写内容。

## 要读的内容块

- `blocks/figure-table.md`：有对比表、参数表时读。
- `blocks/steps.md`：某条里有操作过程时读。
- `blocks/code-sample.md`：条目里有命令或代码时读，如命令速查表。

## 审查清单

- [ ] 条目按读者查找的方式分组，分组方式写在标题或目录里可以看出来。
- [ ] 同组条目结构一致，缺项写了"—"。
- [ ] 没有依赖前文才能看懂的条目。
- [ ] 易混概念有对比表；对比表和参数表逐条通过了 `blocks/figure-table.md` 的审查清单。

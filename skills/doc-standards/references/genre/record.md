# 用途：记录

## 判定

- 留档备查：事后有人要核对当时发生了什么、谁决定了什么、谁要做什么。
- 典型文档：会议纪要、事故时间线、变更记录、CHANGELOG、实验记录、访谈记录。
- 容易混淆：
  - 测试日志、测试事件报告 → `test-docs.md`。
  - 读者要据此做决定 → `genre/decide.md`。
  - 复盘：只要留档经过和原因 → 本用途；要定改进措施，或两者都要 → `genre/decide.md`。

## 结构

1. **元信息**：日期和时间（含时区）、地点或渠道、参与者、记录人。
2. **结论与决定**：每条决定写决定了什么、谁决定。
3. **待办**：每条写事项、负责人、截止日期；缺的写 `【待补：负责人】` 这类占位。
4. **经过**（可选：需要还原过程时）：按时间顺序，每条以时间开头。
5. **未决问题**（可选）。

## 写作规则

- 只记发生了什么和说了什么，不加作者的评价；作者的补充标明是补充。
- 事实、决定、观点分开写：观点写明是谁的观点。
- 时间统一写到分钟，同一份记录用同一时区。
- 记录发出后再改、写 CHANGELOG 时，按 `blocks/revision.md` 写。

## 要读的内容块

- 记录发出后修订、写 CHANGELOG 或变更记录时读 `blocks/revision.md`；其余无必读块。

## 审查清单

- [ ] 元信息写全了日期时间、时区、参与者、记录人。
- [ ] 每条待办都有负责人和截止日期，缺的留了 `【待补】`。
- [ ] 每条决定写了决定人。
- [ ] 观点都标明了是谁的观点。
- [ ] 经过按时间顺序，每条以时间开头。
- [ ] 发出后改过的记录或 CHANGELOG 通过了 `blocks/revision.md` 的审查清单。

# 内容块：需求追溯

## 适用

- 用在：文档里把本文的条目（需求、模块、测试用例）与另一份文档或上下游的条目建立对应关系的地方，包括需求属性里的追溯字段、追踪表、测试用例的追溯字段。
- 各类型特有的做法留在类型文件里：需求的属性集、没有需求编号时改用的编号、测试文档各项规定的追溯字段。

## 写作规则

- 追溯写两个方向：向上指向来源（上层需求、法规、测试依据），向下指向承接它的部件、下层需求、模块或测试。
- 每个条目至少追溯到一个上游条目；上游条目也要列出承接它的下游条目。暂时没有上游或承接者时，写明原因，如"未分配，待研发评审"。
- 引用上游条目时沿用上游文档的原编号，不另编。
- 追溯用表格或条目里的追溯字段给出；双向追溯用一张追踪表，两个方向各占一列，或各写一张表。

## 审查清单

- [ ] 追溯写了两个方向：向上有来源，向下有承接者。
- [ ] 每个条目至少追溯到一个上游条目，每个上游条目至少有一个承接者；暂时没有的，已写明原因。
- [ ] 引用的编号与上游文档的原编号一致。

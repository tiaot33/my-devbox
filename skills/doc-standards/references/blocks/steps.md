# 内容块：编号步骤

## 适用

- 用在：文档里任何要读者按顺序操作的过程，包括教程、操作指南、SOP、部署说明，以及笔记、README 里夹带的一段操作。
- 不适用：带安全风险的实体产品操作，另按 `user-manual.md` 的"操作步骤"和安全信息写。

## 写作规则

- 本文件中，"过程"指一组有序的编号步骤（procedure），"步骤"指其中一步（step）。
- 只有一步、且这一步不含代码块时，写成一句话，用项目符号，不编号；含代码块的单步过程照常用编号 `1.`。
- 步骤前的引导句补充标题里没有的信息；标题已经说清楚任务时省略。
- 引导句写成完整句，如"按以下步骤为团队开通访问权限："，不写由步骤补全的半句；引导句和步骤之间隔着说明段落时，以句号结尾。
- 每步一个动作；连续的菜单选择用 `>` 连接，如"选择**文件 > 导出**"。
- 每步按"位置 → 目的 → 动作 → 结果或理由"的顺序写，结果写在同一步内，不单独编号。界面操作步骤的结果紧跟动作，写在同一段，如"在**设计**选项卡上，选择**标题行**。表格首行会加粗显示。"
- 下一步已经体现了上一步的结果时（如"在弹出的**新建文件**对话框中……"），不再单写一句结果。
- 含命令的步骤按这个顺序写：动作 → 命令代码块 → 占位符说明 → 命令解释 → 输出 → 结果（同一步内另起一段）。
- 引出命令时写命令做什么，如"启动本地服务器："，不写"运行以下命令："。需要按 Enter 时写进同一步。
- 命令写成复制后不用改就能运行的形式；可复制的命令里不写 `[]`、`|`、`{}`、`...` 这类语法记号。
- 输入和输出分成两个代码块。命令有文本输出时，用"输出类似以下内容："引出输出代码块；界面结果写"页面显示……"。
- 输出里每次都不同的值（时间戳、ID），换成占位符，或在代码块后说明哪部分会不同。
- 读者必须替换的值在代码里写成尖括号占位符，如 `<项目名>`，在代码块后逐个说明。
- 密码、令牌、密钥写成环境变量，如 `$API_TOKEN`，在前置条件里说明怎么设置；环境变量不算占位符，不加尖括号。
- 写出收尾动作，如选择**确定**或**应用**。
- 可选步骤以"可选："开头。
- 过程分在多个小标题下时，每个过程开头重新说明操作位置。
- 同一过程在多处要用时，写一处，其他地方链接过去。
- 用界面名称和结构描述位置，如"在**设置**页的**网络**部分"。不用方位词（上方、下方、左侧、右侧、右上角、旁边）；元素难找时写 `【待补：截图，标出 X 的位置】`。
- 界面元素名称去掉末尾的冒号或省略号，只写名称；同一界面上有同名元素时，再加类型词，如"**保存**按钮"。
- 每步只写一种操作方式，写读者最常用的那种；快捷键只在它是最常用方式时写。
- 一个过程用尽量少的步骤，尽量在一屏内放下。

## 审查清单

- [ ] 只有一步且不含代码块的过程写成一句话，没有编号。
- [ ] 每个编号步骤只含一个动作，或只含同一界面位置的连续短动作。
- [ ] 每个说明位置的短语都在动作之前。
- [ ] 软件的响应和结果写在动作所在的步骤里，没有单独编号。
- [ ] 子步骤用嵌套编号列表，不超过三层。
- [ ] 每条命令前写了它做什么；命令复制后不改就能运行，没有 `[]`、`|`、`{}`、`...`。
- [ ] 命令里的每个占位符都在代码块后有说明；用到的环境变量在前置条件里说明了怎么设置。
- [ ] 输入和输出在不同代码块里，输出前有"输出类似以下内容："。
- [ ] 可选步骤都以"可选："开头。
- [ ] 描述界面位置时没有用方位词，位置都用界面名称写出。
- [ ] 界面元素名称加粗；能对照产品时与界面文字一致，不能对照时交付说明里列出了全部界面名称，请用户核对。

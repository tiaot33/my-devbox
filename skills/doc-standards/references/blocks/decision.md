# 内容块：决策与选项

## 适用

- 用在：文档里记录一项已作或待作的决定、比较几个选项、给出推荐，或请读者做决定时。
- 不适用：
  - 单条架构决策记录（ADR）→ `domain-modeling` skill。
  - 整份文档以请读者做决定为目的 → `genre/decide.md`（本块只管其中决策和选项的写法）。

## 写作规则

### 一条决策

- 每条决策写：要决定的问题、选定项、理由、选定项的代价与后果。问题和选定项可以合写成一句，如"库存扣减由同步调用改为经消息队列异步"。
- 理由写出这项决策满足的需求、目标或关注点；对象有编号时写编号。
- 比较过的备选方案和取舍写在决策旁，或链接到写有这些内容的位置。
- 决策尚未生效或已失效时标明状态：待决定、已推迟、已被取代。待决定的写由谁、何时定；已推迟的写去向；已被取代的写取代它的决策。已生效的决策不另标状态。
- 类型文件规定了决策表的列、编号或字段时，按类型文件写。

### 选项比较

- 选项之间用同一组维度比较，写成对比表。
- 每个选项写代价、收益、风险。
- 后果取决于没查实的条件时，写成"<条件>时，<结果>"，并把条件列为未决事项。

### 推荐与事实分开

- 事实（选项的代价、收益、数据）先写完，推荐另起一句或一段写。
- 推荐标明是推荐，并写理由。

### 请读者决定

- 写明要读者决定的事、可选的选项，有截止时间时写截止时间。
- 请求放在文档的什么位置，由用途文件或类型文件规定。

## 审查清单

- [ ] 每条决策写了要决定的问题、选定项、理由和选定项的代价或后果。
- [ ] 每条决策的理由指向它满足的需求、目标或关注点。
- [ ] 比较过的备选方案写在决策旁，或有链接。
- [ ] 待决定、已推迟、已被取代的决策标了状态；待决定的写了由谁何时定，已推迟的写了去向。
- [ ] 选项比较是一张对比表，各选项用同一组维度，每个选项有代价、收益、风险。
- [ ] 取决于没查实条件的后果，写成了"<条件>时，<结果>"，条件在未决事项里。
- [ ] 事实部分没有推荐语；推荐标明是推荐，附了理由。
- [ ] 请读者决定时，写了要决定的事和选项；有截止时间的写了截止时间。

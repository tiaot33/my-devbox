# 内容块：修订与变更说明

## 适用

- 用在：文档发布或发出后再改的地方，包括修订记录、修订说明、更正、撤下或替代旧版本、版本记录（CHANGELOG）、编号条目的增删。
- 各类型特有的做法留在类型文件里：需求基线的变更控制和批准人、个人信息保护政策变更时的告知与重新同意、通知各发布渠道的差异。

## 写作规则

### 版本和日期

- 版本和日期放在文档首部；有修订记录的，记录里每个版本一行。
- 修订记录每次变更一行，写版本、日期、改了什么；需要批准的文档加批准人。
- CHANGELOG 按版本倒序，每个版本按"新增 / 变更 / 修复 / 移除"分组。

### 发布后的改动

- 以下情况写修订说明：新增的信息让读者要换做法；删掉了过时或误导的内容；费用或截止日期变了。只改错别字、样式或失效链接时不写。
- 修订说明用完整的句子，先写最重要的变化，写出改了什么、改在哪里，尽量把改后的内容直接写进说明里："申请表第 2 页第 4 题改为填写原住址。"只写"内容已更新"不合格。
- 记录发出后再改时，在末尾写修订日期和改了什么，不直接覆盖原文。
- 发出后改不了的载体（邮件、短信），内容变了就另发一条，写明它替代哪一条。
- 条款、条目的编号一经发布不重排；删除的条目写"已删除"并保留编号。

### 替代或撤回

- 已发布的公告只为更正错误而改；内容过时就撤下，另发一篇。
- 撤下时留一句说明原因并指向替代内容："本页内容已过时，最新安排见 [链接]。"

## 审查清单

- [ ] 改过的文档附有写明改了什么、改在哪里的修订说明，不是"内容已更新"。
- [ ] 修订说明只用于该写的情况；只改错别字、样式、失效链接的没有写。
- [ ] 修订记录每次变更一行，有版本、日期、改了什么；需要批准的写了批准人。
- [ ] 发出后的改动在末尾写了修订日期和改了什么，原文没有被直接覆盖。
- [ ] 内容变了而原件改不了的（邮件、短信），另发的一条写明了替代哪一条。
- [ ] 撤下的内容留有原因，并指向替代内容。
- [ ] 已发布的编号没有重排，删除的条目保留编号并写"已删除"。
- [ ] CHANGELOG 按版本倒序，并按"新增 / 变更 / 修复 / 移除"分组。

# 快速入门、教程、操作指南

## 适用

- 读者：
  - 教程：第一次接触产品、想学会基本用法的人。读者可能连该问什么都不知道。
  - 操作指南：已经会用产品、手上有具体任务要完成的人。
- 用在：快速入门、分步教程、"如何……"类操作指南、任务型帮助主题，以及升级、迁移、解决某个具体问题的步骤。
- 判定：动笔前回答两个问题。
  1. 文档讲的是做事，还是讲原理？讲原理的见下面"不适用"。
  2. 读者在学（获取技能），还是在干活（应用已有技能）？在学 → 教程；在干活 → 操作指南。
  - 难易程度不作判据：操作指南可以讲基础操作，教程也可以讲复杂内容。
  - 快速入门按教程写，范围收窄到拿到第一个可见结果的最短路径；下文"教程"的规则和清单条目同样管快速入门。读者已会用产品、只想尽快配好某项功能时，按操作指南写。
- 不适用：
  - 以安全须知为主的文档，或涉及人身、设备安全的警示 → `user-manual.md`。步骤里的数据或服务风险仍按本文件写，按 `blocks/warning.md` 写。
  - 命令、参数、接口、选项的完整列表 → `api-reference.md`
  - 项目首页上的简介、安装和用法概览 → `readme.md`
  - 测试用例里的操作步骤 → `test-docs.md`
  - 讲原理、背景的解释性文档：本 skill 尚未收录，告诉用户，只按 `base.md` 写。

## 必需章节

1. **标题**：写出读者要执行的动作，以动词带宾语开头，如"创建并部署一个博客站点""配置重连退避策略"，或写成"用 X 做 Y"；操作指南也可以写成"如何……"。
2. **开头说明**：
   - 教程：一两句说明读者跟着做完会得到什么成果，用"我们"作主语，如"在本教程中，我们将创建并部署……"。
   - 操作指南：一句话说明本指南帮读者完成什么、适用于什么场景，如"本指南说明如何……"。
3. **目标**（可选：教程要在开头列出子任务时加）：用"目标"作小标题，下面直接列出各个过程要完成的任务。
4. **前置条件**（没有前置条件时省略）：在第一步之前列出需要的账号、权限、软件及版本、硬件、已有资源和预备知识。不放进提示框，也不放进某一步里。
5. **步骤**：一个或多个带任务型小标题的编号过程，写法见"写作规则 · 步骤"。
6. **结果确认**：
   - 教程：用"你已经……"说明读者做成了什么、学到了哪些要点，并给出一个确认方法（打开某个地址、运行某条命令看到某个输出）。
   - 操作指南：写出任务完成时读者能看到的状态，然后停在读者可以接回自己工作的位置。
7. **清理**（可选：教程创建了会计费或占用资源的测试资源时加）：给出删除这些资源的步骤。
8. **下一步**（教程必需；操作指南可选）：至少链接一篇相关的操作指南、参考文档或解释性文档；不知道链接目标时写 `【待补：链接】`。

## 写作规则

### 与 base.md 的差异

下面几处按本文件写，base 清单的对应条目按这里判定：

- 称呼：教程的开头和过渡句用"我们"，指作者和读者一起做；步骤用祈使句，不写主语；结果确认用"你"。操作指南按 base 用"你"。
- 标题：任务型标题，以及"目标""前置条件""结果确认""清理""下一步"这些固定标题，满足 base"标题写成陈述句或问题"一条。
- 引导句：固定标题下的列表直接列，不写引导句。
- 步骤列表：步骤下面缩进写的命令代码块、输出、结果、一句解释、出错迹象都属于这一步，不算 base 所说的"描述"。
- 动作数：同一界面位置的连续短动作可以合成一步、写在一句里，如"选择**文件 > 导出**"。
- 加粗：界面元素名称一律加粗，不受 base"加粗只给漏看会出错的内容"的限制。
- 子步骤：Markdown 里写成缩进的 `1.` 嵌套编号列表，最多三层，字母和罗马数字样式交给渲染器；纯文本或 Word 里第二层手写 a、b、c，第三层手写 i、ii、iii。不用 base 的正文序次语。

### 教程

- 用样例数据和事先布置好的环境，让每位读者得到同样的输出。
- 只给一条通往结果的路径，不列选项和替代做法。
- 快速入门按操作系统或编程语言分选项卡写时，选项卡不算替代路径，每个选项卡里只给一条路径。不用选项卡时，选覆盖读者最多的那种，其他平台链接到安装指南。
- 快速入门要用读者自己的账号时，让读者新建一个专用的测试项目，用样例数据，并在"清理"一节删除。
- 让每一步都产生读者看得见的结果，并在步骤里写出预期结果。
- 在容易出错的步骤后写出出错的迹象和最可能的原因，如"如果输出里没有 ……，多半是漏了第 3 步的 ……"。
- 预告会让新手意外的现象：会刷出大量日志、要等较长时间、会弹出某个窗口。要等待时写出大约多久；原始材料没给时长时写 `【待补：等待时长】`。
- 写明基础操作：在哪个窗口或终端里输入、在哪个目录下运行。
- 指出读者应留意的环境变化，如提示符变了、出现了新文件。
- 把解释压到一句话，如"这里用 HTTPS，因为它更安全"，再链接到解释性文档。
- 让步骤可以重复执行，保证读者随时能回到起点；不可逆的步骤按 `blocks/warning.md` 写。
- 改写模式下，原稿的界面、命令或输出有改动时，从改动处往后逐步核对受牵连的步骤，因为一处改动常常牵动后续步骤。
- 在交付说明里写明是否已按步骤实测；没有实测时，在交付说明里写 `【待补：按步骤实测全文，记录卡住的步骤】`。

### 操作指南

- 一份指南只解决一个具体任务或问题。"构建一个 Web 应用"这类开放范围拆成多份。
- 按读者要完成的事划分和命名，不按产品菜单或命令划分；只有一个动作的内容并进相邻的任务。
- 默认读者会基础操作，只写动作；原理和背景链接到解释性文档。
- 给一条推荐路径，场景和示例命令选读者最常遇到的情况。
- 有分支时写成条件句："如果要 X，执行 Y。"确实需要多种完整做法时，分小标题或选项卡写，不在同一组步骤里并列。
- 写出读者真实环境里可能遇到的意外和对策，写在对应步骤里，以"如果……"开头。
- 顺序可以互换的步骤，把为后续步骤准备环境的那一步放前面。
- 选项和参数的完整列表链接到参考文档，如"完整选项见《X 参考》"。

### 步骤（两类共用）

编号步骤的写法和对应检查项见 `blocks/steps.md`，动笔前读。步骤里的警告见 `blocks/warning.md`。

### 英文文档

- 先确定项目跟随 Google 还是 Microsoft 风格指南，同一文档只按一本写。项目自身的风格优先；Google 指南把 Microsoft Writing Style Guide 列为它之下的第三方参考。两本风格指南的主要差异：
  - 点击类动词：Google 用 click；Microsoft 用与输入方式无关的 select，不用 click、swipe。
  - 引导句：Google 要完整句，如 "To customize the buttons, follow these steps:"，不用 "To customize the buttons:"；Microsoft 的示例用 "To create a group of tiles:"。
  - 替代做法：Google 只写最好的一种；Microsoft 要求记录键盘操作，并允许用 "To / Do this" 表格或 "or" 并列写出。按 Microsoft 写时，键盘操作按《输入》另写成单独的文章或表格，不受"每步只写一种操作方式"的限制。
- 每步第一句包含祈使动词，写成完整句，首字母大写、句号结尾，不用 please。需要先说明位置时，以简短的位置短语开头，如 "On the **Design** tab, select **Header Row**."；其他情况以祈使动词开头。
- 任务型标题用动词原形开头，写 "Create an instance"，不写 "Creating an instance"；操作指南可以写 "How to …"。
- 可选步骤和可选小节用 "Optional:" 前缀，不用 "(Optional)"。
- 输出用 "The output is similar to the following:" 引出。
- 复选框用 select 和 clear，不用 check 和 uncheck。
- 教程开头写 "In this tutorial, we will …"，不写 "In this tutorial you will learn …"；结尾写 "You have built a …"。

## 审查清单

- [ ] 标题里有读者要执行的动词并带宾语（如"创建……""用 X 配置 Y"），或以"如何"开头；不是只由名词组成，也不是"X 定时备份"这类没有宾语的短语。
- [ ] 开头一两句写出了成果（教程，以"我们将……"引出）或本指南完成的任务（操作指南）。
- [ ] 前置条件列在第一步之前，没有藏在提示框或步骤里。
- [ ] 编号步骤逐条通过了 `blocks/steps.md` 的审查清单。
- [ ] 教程：每一步都写出了预期结果或输出，或者下一步的开头已经体现了这个结果。
- [ ] 教程：全篇只有一条路径，没有"也可以……""或者……"式的替代做法，也没有"如果你要……"式分支。
- [ ] 教程：用的是样例数据或专用测试项目，不是读者的真实数据。
- [ ] 教程：会刷出大量输出或需要等待的步骤预告了现象和大约时长，或留有 `【待补】`。
- [ ] 教程：每段解释不超过一句，其余放在链接里。
- [ ] 教程：不可逆的步骤逐条通过了 `blocks/warning.md` 的审查清单。
- [ ] 教程：创建了计费或占用资源的测试资源时，有清理一节。
- [ ] 教程：交付说明写明了实测结果，或留有实测的 `【待补】`。
- [ ] 操作指南：范围是一个具体任务，标题按读者的任务命名，不按菜单或命令命名。
- [ ] 操作指南：开头没有"带你学习""你将学到"式的教学说法，正文没有成段的原理或背景说明。
- [ ] 操作指南：分支写成"如果……，执行……"；多种完整做法分在不同小标题或选项卡下。
- [ ] 操作指南：真实环境里可能出现的意外写在对应步骤里，以"如果……"开头，并给了对策。
- [ ] 操作指南：完整选项列表链接到参考文档，没有在步骤里铺开。
- [ ] 教程结尾有结果确认和下一步；操作指南结尾有结果确认。
- [ ] 英文文档：全篇只按一本风格指南的动词和引导句写法。

## 示例

改写前（教程中的一段）：

```markdown
注意：请先安装 Docker。
1. 运行以下命令：`docker run -p 8080:80 nginx`
2. 容器启动。
3. 你也可以加 `-d` 在后台运行，或者改用 docker compose。
```

改写后：

````markdown
## 前置条件
- Docker（运行 `docker --version` 能输出版本号）
## 启动 Nginx
1. 在终端中启动一个 Nginx 容器，把容器的 80 端口映射到本机的 8080 端口：
   ```bash
   docker run -p 8080:80 nginx
   ```
   终端持续输出访问日志。保持这个窗口打开。
2. 在浏览器中打开 `http://localhost:8080`。页面显示 "Welcome to nginx!"。
   页面打不开时，8080 端口可能已被占用。把第 1 步命令里的 `8080` 换成 `8081`。重做第 1 步。
````

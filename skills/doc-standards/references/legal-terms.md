# 用户协议、隐私政策、披露文件

## 适用

- 读者：没有法律背景的用户。注册或首次使用时跳读，出了争议、想删数据、想退出时回来查具体条款；其中可能有儿童、老人和阅读能力受限的人。律师、监管人员也会读。
- 按最不熟悉的读者写。这一点与 base "按主要读者写"不同：条款约束每一个读者，最不熟悉的读者最需要读懂它。
- 用在：用户协议、服务条款、保修条款、隐私政策（个人信息保护政策）、App 内的增强告知和即时提示、面向投资者的发行披露文件。App 的个人信息收集清单和第三方共享清单按隐私政策写。
- 边界：本文件管写法，不提供法律意见。下面这些判断写成 `【待补：法务确认……】`，不自行下结论：
  - 某项信息是否属于敏感个人信息
  - 哪些处理需要单独同意
  - 每个处理目的的法律依据
  - 法定保存期限
  - 格式条款是否有效
  - 各语言版本是否同等有效
- 不适用：
  - 产品的安全须知，以及使用说明里怎样申请保修的操作步骤 → `user-manual.md`
  - 告知条款或政策变了的那份通知，以及服务调整、停服这类其他对外通知 → `public-notice.md`
  - 给阅读困难读者的易读版协议或政策，包括面向儿童本人的版本 → `register/easy.md`
  - 国内证券发行和上市公司的信息披露：章节按证监会格式准则，本文件只管其中的语言写法；准则未收录，在交付说明里告诉用户对照原文。
  - 标准、规范文件 → `standard.md`；党政机关公文 → `gov-doc.md`

## 必需章节

下面的章节名是内容槽，不是固定标题。成文时按"结构与分层"一节改成读者的问题，如"适用范围"→"这份政策管什么、我们是谁"。

### 隐私政策（个人信息保护政策）

1. **适用范围**：适用的产品或服务、适用的个人类型、生效日期和最近更新日期；写一句"我们"指哪个法律主体（全称）。
2. **重点说明**：简短摘要，写处理目的、处理者身份、你有哪些权利，以及影响最大或可能出乎读者意料的处理。
3. **我们是谁**（可以并进第 1 节）：处理者的名称或姓名、联系方式；面向欧盟用户时加数据保护官（DPO）的联系方式。
4. **各业务功能收集哪些信息**：每个功能收集什么、用来做什么、怎样收集，写法见"告知内容写具体"。每个功能下分别写必要信息"共计 N 类"、可选信息"共计 M 类"；申请系统权限时写"共计 K 项系统权限"。敏感个人信息单独标识，并写明处理它的必要性和对你的影响。
5. **保存期限和地点**：每类信息保存多久、存在哪里、是否出境。
6. **委托处理、向其他处理者提供、转让、公开披露**：每个接收方标明属于这四类中的哪一类，写目的、处理方式、信息种类；分类和是否需要单独同意写 `【待补：法务确认】`。向境外提供时，加写境外接收方的联系方式，以及你向它行使权利的方式。
7. **自动化决策**（可选：有画像、推荐、自动审批时）：做什么决定、你怎样要求说明、怎样拒绝。
8. **你的权利和怎样行使**：查询和复制、更正、删除、注销账户、撤回同意、转移到其他处理者（满足网信部门规定的条件时）、要求解释规则。行使方式的写法见"告知内容写具体"。
9. **提供信息的风险和不提供的后果**：写提供信息后可能存在的安全风险，以及不提供某类信息时哪些功能用不了。后者已写进第 4 节对应的功能下时，这里汇总一句。
10. **我们怎样保护你的信息**：安全措施，有合规证明时写出。
11. **儿童的个人信息**（可选：可能有不满十四周岁的用户时）：在本政策里写一节，说明需要监护人同意的情形和监护人怎样操作。专门的儿童个人信息处理规则是另一份文档，在交付说明里提醒用户另起任务写。
12. **法律依据和正当利益**（可选：面向欧盟用户时）：每个处理目的对应的法律依据。
13. **本政策怎样更新**：哪些变更算重大变更、我们怎样通知你、旧版本在哪里查，写法见"政策怎样更新"。
14. **怎样询问和投诉**：负责部门或专人的联系方式、回复时限、外部投诉渠道（监管机构、纠纷解决机构）。联系方式与第 3 节相同时只写一处，另一处指过去。

### 用户协议、服务条款、保修条款

顺序迁移自 JPG 指南 15 的标准结构。

1. **适用范围**：协议双方是谁（"我们"指哪个法律主体全称，"你"指谁）、适用的产品或服务、生效日期。读者读完这一节就能判断自己是否受约束。
2. **重点说明**（可选：协议超过 2 000 字时）：读者最需要知道的义务、费用、限制和例外。
3. **定义**：只收一词多义、或含义比日常含义更窄或更宽的词。
4. **权利和义务**：一节内分条写"你的权利和义务""我们的承诺""我们可以做的事和条件"，前后不矛盾。
5. **费用和怎样办理**：收费项目和金额；开通、付费、自动续费和取消续费、退款、注销的流程，按步骤写。
6. **我们不承担哪些责任**：免除或减轻我们责任的条款逐条列出，每条写成短句并突出显示，标 `【待补：法务确认】`。
7. **协议怎样变更和终止**：协议怎样变更、怎样通知你、双方怎样终止。
8. **怎样联系我们、投诉和解决争议**：客服和投诉渠道、回复时限、外部纠纷解决渠道；适用法律和管辖写 `【待补：法务确认】`。

### 披露文件

1. **封面**：读者做决定所需的关键事实，不求讲完。
2. **摘要**：只放要点，不整段复制正文。
3. **风险因素**：每项要写的内容由用户按适用法规提供，缺的写 `【待补：法规要求的风险披露项】`。Rule 421(d)(2) 只规定这部分的写法，见"披露文件"规则。
4. **正文**：法规要求披露的各项；法规条目由用户提供，缺的写 `【待补：法规要求的披露项】`。

## 写作规则

### 结构与分层

- 隐私政策和用户协议分开成文；用户协议里需要提到个人信息时，写一句话并链接到隐私政策。
- 摘要层（重点说明、弹窗、增强告知）只摘正文已有的内容，措辞与正文一致，不增删条件。同一内容说两遍且说法不同，会引发以哪一处为准的争议。
- 每个摘要层末尾写明完整内容在哪里。
- 完整政策放在一个页面或一个文件里，分层只用于摘要。
- 正文设定的每项义务都落在范围条款写明的对象和服务之内。
- 定义只说这个词指什么，义务和例外写进正文条款。
- 给最不熟悉的读者补的基础解释，放在视觉上可区分的说明框里，让专业读者能跳过。
- 标题不含法律术语，写读者的问题，如"我们会把你的信息给谁"。
- 条款编号用数字分级；条款里的并列项也用数字或字母编号，方便争议时交叉引用。与 base 不同：base 只给有先后顺序的列表编号。

### 告知内容写具体

- 按业务功能逐项写"使用 X 功能时，我们收集 Y，用来 Z"，每个目的对应具体的信息种类。
- 写确定的事实，如"我们会收集""我们不会出售"。
- 用"可能""某些""有时""包括但不限于""尽力""合理""适当""必要的"时，在句中写出确定的条件。
- 用了上一条的词时，在工作记录里写明为什么无法确定；审模式没有工作记录，只查句中条件。
- 保存期限写成具体时长或可核对的标准，如"注销账户后 30 天内删除"；"在必要期限内"只在后面紧跟具体标准时用。
- 每项权利写出入口和步骤（在哪个页面、点哪个按钮、发到哪个邮箱）和回复时限。
- 撤回同意的写法与给出同意的写法放在一起，路径同样短。
- 复杂、技术性或读者想不到的处理，在法定事项之外单独写一段说明对读者的实际后果。
- 接收方能写名称就写名称；只能写类型时，写到读者能判断是哪类公司，如"支付机构""云存储服务商"。
- App 接入的第三方 SDK 和其他自动化工具，逐个写名称和提供方，再按第 6 节写目的和信息种类。
- 接收方和 SDK 名单可以单独成页，从第 6 节链接过去；面向欧盟用户时放在政策的同一页面。
- 引用法律条文时，在引文后写出它对读者的要点，让读者不翻原文也能读懂。

### 措辞

- "我们"指发布方，"你"指读者；英文写 we/us/our 和 you/your。
- 用户或项目已统一用"您"时跟随，全文只用一种。与 base 不同：国内协议和政策模板多用"您"。
- 指双方时不写"本公司""甲方""乙方""用户""您方"；指读者以外的人时可以写"其他用户"。
- 四类句子用四种写法，全文固定：
  - 我们的承诺：写"我们会""我们不会"。
  - 你的义务：写"你必须""你不得"。
  - 你的权利和选择：写"你可以"。
  - 我们保留的权利：写"我们可以"，同一句写出触发条件，如"你发布违法内容时，我们可以删除该内容"；不写"我们有权""我们保留……的权利"。
- 在定义节或开头说明"必须""会""可以"在本文中各表示什么。
- 说明我们怎样做的内容用陈述句，不写成对读者的命令。
- 否定加例外改成"只有……才"："除非你同意，否则我们不会共享"→"只有你同意后，我们才会共享"。英文把 not … unless 改成 only if，not … until 改成 only when。
- base 的条件列表和表格规则之外，条款句还按下面的语序写：
  - 一个条件对应多个结果时，先写条件。
  - 多个条件对应一个结果时，先写结果。
  - 多对多时先拆成几句，每句写明哪个条件对应哪个结果；仍然不清楚时才用表格。与 base 不同：base 直接用表格。
- 两组内容配对时，每一对单独写一句，代替"分别"；英文同样不用 respectively。
- 古旧或公文腔的法律用语换成日常说法："兹""业经""本协议项下"改成直接陈述。
- 日常意思和法律意思不同的词（如"转让""公开披露""同意"）保留原词，写出它在本文中的意思：用户协议收进定义节，隐私政策在首次出现处写。与 base 不同：这类词是法律规定的用语，换词会改变法律含义，所以不按 base "另选一个词"处理。
- 面向境内读者时提供规范简体中文版；有其他语言版本时，每个版本都能独立读通。
- 原稿里"继续使用即视为同意""最终解释权归……所有"这类条款，改写时既不删除，也不照搬，标 `【待补：法务确认】`。

### 强调与版式

- 突出显示只给四类内容：敏感个人信息、对你的权益有显著影响的条款、规则的重大变化、格式条款中免除或减轻我们责任的内容。
- 默认用加粗；产品界面已用字号或颜色突出时，可以改用字号或颜色，全文只用一种方式。与 base "强调只用加粗"不同，因为 42574 认可这三种方式。
- 界面路径和按钮名用引号，不加粗，免得和上面四类突出内容混在一起。
- 免责、限制类内容不整段加粗或全大写；改写成短句后，只突出关键句。
- 图表按比例画，坐标和比例不夸大或缩小差异。
- 复杂流程（如注销、跨境传输的路径）配流程图或表格。
- 在交付说明里提醒用户：政策链接放在首页或安装页的显眼处。面向境内用户时，从主界面打开不超过 4 次点击或滑动；面向欧盟用户的 App，隐私信息不超过两次点击。

### 政策怎样更新

- 更新记录和旧版本的处理按 `blocks/revision.md` 写，本节只写政策变更特有的告知要求。
- 写明我们会怎样通知你（登录弹窗、推送、邮件、短信中的哪几种），代替"请定期查看本政策"。
- 处理目的、处理者身份、权利行使方式、接收方类型、跨境传输的变化写成重大变更；错别字和文字修正按一般更新处理。

### 披露文件

- 封面、摘要、风险因素用日常说法写，不用定义节里的定义词和法律术语。
- 逐段判断这段是法定要求，还是能帮读者做决定；两者都不是的段落删掉。

## 审查清单

通用：

- [ ] 第一节内写明了"我们"对应的法律主体全称、适用的产品或服务、生效日期。
- [ ] 全文对读者只用"你"或"您"中的一个，对发布方只用"我们"；没有用"本公司""甲方""乙方""用户""您方"指代双方。
- [ ] 每个标题都是读者的问题或陈述，不含定义节里的定义词，也不含"兹""业经""项下"。
- [ ] 定义节里没有义务、例外或承诺。
- [ ] 每个日常意思和法律意思不同的词都写了本文中的意思。
- [ ] 承诺、义务、权利和选择、我们保留的权利都用"措辞"一节规定的写法；没有"我们有权""我们保留……的权利""您应""我们将尽力"。
- [ ] 每个"我们可以"句都写了触发条件。
- [ ] 没有"除非……否则不""不……除非"这类否定加例外的写法。
- [ ] 没有用"分别"配对的句子。
- [ ] 每个"可能""某些""有时""包括但不限于""尽力""合理""适当""必要的"所在的句子都写出了确定的条件。
- [ ] 每处引用法律或其他文件都写了被引内容的要点。
- [ ] 每个摘要层（重点说明、弹窗、增强告知）的每句话都能在正文找到对应条款，条件没有增减。
- [ ] 每个摘要层末尾写明了完整内容的位置。
- [ ] 突出显示只用于"强调与版式"列出的四类内容，全文只用一种方式；没有整段加粗或全大写，界面路径没有加粗。
- [ ] "适用"一节列出的法律判断，以及"视为同意""最终解释权"条款，都写成了 `【待补：法务确认……】`。

隐私政策：

- [ ] 隐私政策和用户协议是两份文件。
- [ ] 包含必需章节第 1–6、8–10、13、14 节（第 3 节可以并进第 1 节）；有儿童用户、自动化决策、欧盟用户时，对应的可选节都在。
- [ ] 收集的信息按业务功能分节，每节写了种类、目的、收集方式，并分别写了必要信息和可选信息的类数。
- [ ] 每处敏感个人信息都有突出标识，并写了必要性和对读者的影响。
- [ ] 每类信息的保存期限是具体时长或可核对的标准。
- [ ] 每项权利都写了入口、步骤和回复时限。
- [ ] 撤回同意的路径写在给出同意的说明旁边。
- [ ] 每个接收方都标明了委托处理、提供、转让、公开披露中的哪一类，并写了名称或具体类型、目的、信息种类；有出境时写了境外接收方。
- [ ] 每个第三方 SDK 都写了名称和提供方。
- [ ] 没有要读者自己定期查看政策的话；文中写明了通知变更的方式。

用户协议、服务条款、保修条款：

- [ ] 包含必需章节第 1、3–8 节。
- [ ] 每条免除或减轻我们责任的条款都已突出显示，并标了 `【待补：法务确认】`。

披露文件：

- [ ] 有封面、摘要、风险因素；风险因素缺的法定披露项写成了 `【待补：法规要求的风险披露项】`。
- [ ] 封面、摘要、风险因素里没有定义节中的定义词和法律术语。

## 示例

改写前：

```markdown
为了向您提供更优质的服务，我们可能会收集您的设备信息、位置信息等相关信息，
并在必要期限内予以保存。除非法律另有规定，否则我们不会向第三方提供您的信息。
请您定期查看本政策以了解更新情况。
```

改写后：

```markdown
使用"附近门店"时，我们收集你的**精确位置（敏感个人信息）**，只用来列出 5 公里内的门店。
不开启定位，你仍可以手动输入城市查找门店。
我们不保存位置记录，查找结束后立即删除。
只有你单独同意，或法律要求时，我们才会把你的信息提供给其他公司。
本政策有重大变更时，我们会在你下次登录时弹窗通知。
```

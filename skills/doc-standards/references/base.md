# 通用写作基础

## 适用

- 读者：按本 skill 写、改写、审查任何类型文档的 agent。
- 用在：所有类型文件共用的语言层。类型文件对同一事项有更严或不同的要求时，按类型文件。
- 不适用：
  - 原样引用的代码、命令、命令输出、日志、错误信息、界面文案：保持原文。
  - 给阅读困难读者的易读版 → `easy-read.md`。ISO 把 plain language 与 easy language 分开处理。
  - 规范性文件的助动词（应、宜、可等）→ `standard.md`
  - 公文的格式和用语 → `gov-doc.md`

## 写作规则

### 读者与目的

- 动笔前在交付说明里写下三件事。交付说明是交给用户时附在文档外的说明，不进正文。
  - 读者是谁：主题知识、语言能力、无障碍需求。
  - 读者读完要做什么：完成任务、做决定或理解主题。
  - 读者在什么情况下读：设备、时间、专注程度。
- 有多类读者且需求冲突时，按主要读者写；需求差别大时，给不同读者分开写不同小节或文档。
- 列出读者需要回答的问题，按这些问题选材。读者不需要的内部流程、背景、作者自己的工作经过，删掉。
- 读者需要知道的限制、费用、风险、例外都写出来，即使对作者不利。
- 直接用"你"称呼读者，全文统一；"你"指谁不明显时，在开头说明。
- 替最终读者写：审稿人关心而读者不关心的内容，放进交付说明。
- 每个事实都要能在原始材料里找到。找不到的写 `【待补：缺什么】`，留给用户填；数字、名称、界面路径都不自行补。
- 文档面向公众、影响读者的权利或钱款时，在交付说明里建议用户做复述测试：请目标读者用自己的话说出文档要他做什么，不问是非题。

### 结构

- 把读者最需要的信息放在开头：结论、要读者做的事、摘要。
- 内容排序：已知信息在前、新信息在后；操作按时间顺序；多数读者需要的在前、少数读者需要的在后。
- 不按顺序做会造成损害时，把"先确认什么、不得做什么"写在对应操作之前。
- 警告第一句写必须做或不得做的事，第二句写不遵守的后果。
- 标题写成陈述句或问题，概括本节结论或回答的问题："缓存满了以后旧条目会被删除""怎样申请退款"。
- "概述""说明""其他"这类标题只在类型文件要求时用。
- 每段第一句写本段要点，读者只读各段首句就能把握全文。
- 一段一个主题，一段不超过 6 句。
- 补充材料（推导、历史、完整数据）和正文分开，放附录或链接。
- 文档超过 2 000 字或有 5 个以上二级标题时，给目录。

### 句子

- 一句只写一个动作或一个事实。
- 步骤句不超过 30 字，描述句不超过 40 字。计数：汉字、英文单词、数字、代码标识符各计 1 字，标点不计。英文阈值见"英文文档"。
- 拆长句时保留"但是""所以""因此"这类连接词，让拆开的句子仍然连贯。
- 写出动作的执行者，用主动句："过期文件被删除"→"系统删除过期文件"。执行者未知或与读者无关时，可以用被动。
- 主语省略后有两种读法时，补出主语。
- 代词或时间指代（它、这、该、届时、上述）可能指向两个以上对象，或所指的对象前文没有出现时，换回所指的名词或时间。
- 条件写在动作前："连接失败时，显示错误。"
- 一句里的例外或条件多于一个时，拆成列表；何时改用表格见"版式"。
- 用肯定句："不能不确认"→"必须确认"。例外只写一层，例外里不再套例外。
- 读者要记住的内容放在句末。
- 写出具体的量："并发数会影响内存"→"每增加 1 000 个并发连接，内存增加约 200 MB"。

### 用词

- 用具体动词替换"进行""予以""加以""做好……工作"这类虚化动词。常见替换：
  - 对 X 进行修改 → 修改 X
  - 作出 X 决定 → 决定 X
  - 通过 X 的方式 → 用 X
  - 存在 X 问题 → 写出具体现象
  - 有一定的 X → 写出具体的量；没有量时删掉
  - 实现 X 功能 → 增加 X，或写出 X 的具体行为
  - "处理"也是虚化动词：能写出具体动作时，写具体动作。
- 一个名词串最多 3 个名词，超过时用"的""时""中"拆开："终端会话失败反馈界面状态"→"终端会话失败时的界面状态"。
- 同一意思有日常说法和术语两种写法、读者不是本领域人员时，用日常说法，并在首次出现处括注术语。
- 删掉"众所周知""值得注意的是""在一定程度上"这类不带信息的套话。
- 列举写全，或写出完整清单在哪里，结尾不用"等""之类"。省略号和"等"不同时用。
- 表示"或""和"时写汉字："X/Y"→"X 或 Y"，"X 和/或 Y"→"X 或 Y，或两者都"。"/"只用于路径、层级、类别。
- 异形词用 GF 1001-2001 的推荐词形，如用"参与"，不用"参预"。
- 代码标识符、命令、路径放进反引号。界面元素名照界面原样写，加粗或加引号按项目约定，全文统一；项目没有约定时加粗。

### 术语

- 一个词在全文只表示一个意思，一个意思在全文只用一个词。改写或拼合多份材料时，先统一术语再动笔。同一概念重复出现时，重复用同一个词。
- 术语在首次出现处用括号定义。读者不熟悉的术语多于 5 个，或文档超过 2 000 字时，另给术语表。读者已知的通用词不定义。
- 需要专门概念时，另选一个日常意思不冲突的词。
- 缩写首次出现时写全称并括注缩写，之后统一用缩写；全文只出现一两次的，直接写全称；读者人人都懂的缩写（如 URL）不展开。
- 外文术语全文用同一个译法，首次出现时可以括注原文；项目已有译名表时按译名表，例如 procedure 译"步骤"、note 译"说明"。
- 同一缩写在不同领域含义不同时，在首次出现处写明本文取哪个意思。

### 受控情态词

只用下面三个词表达义务、禁止和许可，每个词的意思全文固定：

| 用词 | 意思 | 换成左列用词的近义说法 |
| --- | --- | --- |
| 必须 | 强制要求 | 应、应当、应该、需要、务必、要 |
| 不得 | 禁止 | 不应、不要、避免、禁止、切勿、不允许 |
| 可以 | 允许，不强制 | 可、能够、允许、可选 |

- 表中近义说法只在表示义务、禁止、许可时替换。下面几种用法照用：依赖（"这一步需要管理员权限"）、意图（"要保留的数据"）、能力（"系统能够承载 1 000 QPS"）、目的（"为避免数据丢失"）、复合词（"可用""不可逆"）。
- 引用来源原文时保留原文用词，加引号。
- 禁止项能改写成要做的动作时，写动作："不得在生产库上运行"→"只在测试库上运行"。
- 表达建议时，写出理由或适用条件，让读者自己判断："数据超过 1 万条时，分批导入更快"。本文件没有建议级情态词。

### 标点

- 中文正文用全角标点；代码、命令、路径和英文句子内部用半角标点。
- 引号用"“”"，引号里再套引号用"‘’"。项目已统一用直角引号「」时，跟随项目。
- 中文与英文单词、数字之间是否加空格，跟随项目已有约定；没有约定时加一个半角空格，全角标点前后不加空格。
- 一句里只用一个冒号；需要多层提示时另起段落或用列表。
- 标了引号或书名号的并列成分直接相连："《标准 A》、《标准 B》"→"《标准 A》《标准 B》"。
- 分句内部已用逗号时，分句之间用分号。
- 括号用圆括号"（）"；括号里套括号时，内层用方括号。句内括号里的文字末尾不加标点。量值表达式的括号见"数字与单位"。
- 破折号写"——"（占两字），省略号写"……"（六点）。
- 文章标题、小标题、图表的短语式说明文字末尾不加句号。
- 书名号只用于作品名，以及中文为主的软件名；课程、会议、组织机构、商标、证照用引号或不加标号。
- 正文里的序次语按"一、"→"（一）"→"1."→"（1）"→"①"逐层往下用；"（1）"后直接接文字；"3.1"这类章节号后空一格。

### 数字与单位

- 计量和编号用阿拉伯数字，尤其是带单位的数值；概数、含"几"的数、定型词语（"一律""星期五"）用汉字数字。
- 同一文档里同类数字用同一种写法："第一章……第 12 章"→"第 1 章……第 12 章"。
- 一个数值里只用一种数字："4千"→"4000"。很大的数值可以用"万""亿"，如"10 亿"。
- 纯小数写出小数点前的 0：0.46。
- 数值范围用浪纹线"～"。省略前一个数值的单位或符号会产生歧义时，两端都写："9～16 亿"→"9 亿～16 亿"。
- 日期写"2026 年 10 月 20 日"或"2026-10-20"，同一文档只用一种。写出年份时写四位；上下文已有年份时，同年的日期可以省略年份。年月日不全时用汉字："2026-10"→"2026 年 10 月"。
- 时刻用 24 小时制，写"15:40"。
- 技术文档的多位数从小数点起每三位空一格分组："共 12 500 条记录""3.141 59"。四位整数可以不分组，同一文档统一。其他文档跟随项目约定，千分撇和千分空都可以。
- 数值和单位符号之间空一格，℃ 前也空："20 ℃"。平面角的度、分、秒和百分号紧贴数值："30°""15%"。词头和单位符号之间不空："kPa"。
- 带误差或运算的量加半角括号再写单位："28.4±0.2 ℃"→"(28.4±0.2) ℃"。
- 单位用符号且整体使用："摄氏 20 度"→"20 ℃"；组合单位只用符号："km/小时"→"km/h"。
- 选倍数单位让数值落在 0.1～1 000 之间："1 401 Pa"→"1.401 kPa"。数值对应配置项、界面或接口字段时，照原单位写：配置是 `timeout_ms=5000` 时写"5000 ms"。

### 版式

- 并列项有三个以上，且每项多于一个短语或读者要逐项核对、选择时，写成竖排列表。短词并列留在句内，用顿号："Linux、macOS、Windows 都支持"。
- 列表前写一句引导句，以冒号结尾。
- 有先后顺序的步骤用编号列表，其余用项目符号。
- 步骤和描述分成两个列表。
- 列表只用一层。
- 条件组合多于两种时，用"条件 / 结果"两列的表格。
- 强调只用加粗，只给读者漏看会出错的内容。界面元素名的加粗按"用词"一节，不算强调。
- "说明""注"只放补充信息；读者必须做的事写进正文或步骤。
- 链接文字写出目标内容："点击这里"→"见《安装指南》"。
- 交叉引用写出被引内容："见上文"→"见第 3 节'退款条件'"。

### 英文文档

- 义务写 must，禁止写 must not，许可写 may，全文不用 shall。
- 句子平均 20 词左右，中间夹几个短句。按 STE 写时，步骤句不超过 20 词，描述句不超过 25 词。
- e.g.、i.e.、etc. 改成完整说法：for example、such as、that is、and so on。
- 一篇文档里需要读者记住的缩写不超过三个。

## 审查清单

- [ ] 交付说明写明了读者、读者读完要做的事、阅读情境（审模式看不到交付说明时标不适用）。
- [ ] 开头一段写出了结论或读者要做的事。
- [ ] 正文没有作者的工作经过和读者用不到的内部流程。
- [ ] 每个事实都能在原始材料里找到，缺的写成了 `【待补：缺什么】`。
- [ ] 称呼读者用"你"，全文统一。
- [ ] 每个标题都是陈述句或问题，或是类型文件规定的固定标题。
- [ ] 每段不超过 6 句，首句是本段要点。
- [ ] 有损害风险的操作，警告写在操作之前，且第一句是必须做或不得做的事。
- [ ] 没有步骤句超过 30 字、描述句超过 40 字（按"句子"一节的计数法）。
- [ ] 每句只含一个动作或一个事实。
- [ ] 每个条件句的条件写在动作之前。
- [ ] 每个被动句都属于执行者未知或与读者无关的情况。
- [ ] 没有所指不明的代词或时间指代（它、这、该、届时、上述）。
- [ ] 没有双重否定。
- [ ] 没有"进行""予以""加以""做好……工作"作谓语；能写出具体动作的地方没有用"处理"。
- [ ] 没有"众所周知""值得注意的是"这类套话。
- [ ] 没有超过 3 个名词的名词串。
- [ ] 列举没有以"等""之类"收尾。
- [ ] 正文没有用"/"表示"和"或"或"。
- [ ] 每个术语在首次出现处或术语表里有定义。
- [ ] 每个缩写首次出现时有全称，或属于人人都懂的缩写。
- [ ] 同一概念全文只用一个词，同一外文术语只用一个译法。
- [ ] 表示义务、禁止、许可的句子只用"必须""不得""可以"。
- [ ] 中文正文用全角标点；代码、命令、路径在反引号内。
- [ ] 引号、中英文间空格、界面元素名的写法全文统一。
- [ ] 标题和图表说明末尾没有句号。
- [ ] 序次语按"一、""（一）""1.""（1）""①"逐层使用。
- [ ] 同类数字写法统一，没有"4千"式混写，纯小数有前导 0。
- [ ] 数值范围用"～"，省略单位不产生歧义。
- [ ] 日期写法全文统一，写出的年份是四位，不完整的年月日没有用短横线；时刻用 24 小时制。
- [ ] 数值与单位符号之间有空格（度分秒和 % 除外），组合单位没有混用中文。
- [ ] 带单位的数值落在 0.1～1 000 之间，或照用配置项、界面、接口字段的原单位。
- [ ] 需要列表的并列项（三个以上，且每项多于一个短语或要逐项核对）写成了列表，列表前有引导句。
- [ ] 没有同时含步骤和描述的列表。
- [ ] 加粗只用在漏看会出错的内容和界面元素名上，没有下划线强调。
- [ ] 每个链接文字和交叉引用都写出了目标内容。
- [ ] 英文文档的义务只用 must，没有 shall，没有 e.g.、i.e.、etc.。

## 示例

改写前：

```markdown
众所周知，系统会在每天凌晨3点对超过30天的缓存进行清理工作，数据会被删除，用户应该注意备份/导出等相关事项。超时时间为.5秒到2秒。
```

改写后：

```markdown
系统每天 03:00 删除超过 30 天的缓存条目。删除后能否恢复：【待补：能否恢复】。

要保留这些数据，必须在删除前备份或导出。导出入口：【待补：导出功能的菜单路径】。

超时时间是 0.5 s～2 s。
```

# 按标准写文档

每次只处理一份文档：定模式，定要读的文件，写，按清单自查。

## 1. 定模式

三选一：

- **写**：从零写。
- **改写**：用户给了原稿。保留原稿的事实，改结构和文字。
- **审**：只交问题清单，不动原文。

用户给的是原始材料（会议转写、零散笔记、聊天记录、数据）而不是同类文档的原稿时，算"写"，材料作为事实来源。

一次要多份文档（如"补 README 和 API 文档"）时，按文档拆成独立任务。每份可以单独交给一个 subagent 或 workflow，只给它第 2 步选出的文件和原始材料。

## 2. 定要读的文件

文件都在 `references/` 下。按顺序走，前一步定下来就不再往下走。

**2.1 有专门类型文件的，用类型文件。** 文档属于下表某一行，或用户点名了该行的标准时：

| 大类   | 文档类型             | 文件                   |
| ---- | ---------------- | -------------------- |
| 用户文档 | 用户手册、使用说明、安全须知   | `user-manual.md`     |
|      | 快速入门、教程、软件操作指南   | `tutorial.md`        |
|      | API 参考、SDK 文档    | `api-reference.md`   |
|      | README           | `readme.md`          |
| 开发过程 | 需求规格说明、PRD       | `requirements.md`    |
|      | 架构描述             | `architecture.md`    |
|      | 设计说明（模块、接口、数据）   | `design.md`          |
|      | 测试计划、测试用例说明、测试报告 | `test-docs.md`       |
|      | 文档计划、文档外包需求      | `doc-plan.md`        |
|      | CONTRIBUTING、行为准则；按 GB/T 8567 或 15289 写的其他开发过程文档 | `lifecycle-other.md` |
| 对外   | 通知、公告、对外说明       | `public-notice.md`   |
|      | 用户协议、隐私政策、披露文件   | `legal-terms.md`     |
|      | 面向公众的科普文章        | `popular-science.md` |
| 报告   | Agent 给用户的结果汇报   | `agent-report.md`    |
|      | 科技报告             | `tech-report.md`     |
|      | 学术论文、学位论文        | `thesis.md`          |

读 `base.md` 和这个类型文件，再读类型文件里点名的 `blocks/` 文件，以及这些块文件里点名的其他块文件。标为按条件读的块，写到相应内容时再读。

**2.2 表里没有的，按用途选。** 对文档的主要读者问"读完要做什么"，从上往下，第一个"是"就选它：

| 读者读完要…… | 文件 | 例子 |
| --- | --- | --- |
| 按顺序操作，完成一件事 | `genre/do.md` | SOP、部署步骤、值班处置手册 |
| 遵守、执行或签认 | `genre/agree.md` | 团队规范、编码约定、SLA |
| 做决定，或判断进展是否正常 | `genre/decide.md` | 周报、方案对比、选型、提案 |
| 留档，事后核对发生了什么 | `genre/record.md` | 会议纪要、事故时间线、CHANGELOG |
| 回来查某一点或快速回忆（读者已经懂） | `genre/lookup.md` | 复习笔记、速查表、FAQ |
| 第一次弄懂一个概念或原因 | `genre/understand.md` | 原理讲解、技术博客、入职介绍 |

一份文档只选一个主用途。其中某一节明显是别的内容（如笔记里夹着一段操作过程），那一节按对应的 `blocks/` 文件写。读 `base.md`、选中的用途文件，以及用途文件里点名的 `blocks/` 文件（连同这些块文件里点名的其他块文件）。

**2.3 选语体。** 默认是完整语体，只读 `base.md`。只有下面两种情况追加文件：

- **精简**：用户明说要"简洁""精简""要点""速查""一页纸"，或文档只给作者本人看（如自己的复习笔记）：追加 `register/concise.md`。文档是周报、纪要，或读者是同事，都不算，除非用户明说。
- **易读**：用户要"易读版"，或读者阅读有困难：追加 `easy-read.md`。原文属于 2.1 的某一类型时，那个类型文件照读。

2.1 和 2.2 都判断不出时，问用户这份文档给谁看、读完要做什么。图表和仪表盘转 `dataviz`，ADR 转 `domain-modeling`。

**完成标准：** 模式、要读的文件清单、目标读者、输出语言都已确定。读者和语言没说时，从原稿和上下文推断；推断不出就问。

## 3. 读规则

读第 2 步选出的全部文件。规则冲突时，按这个顺序取前者：类型文件 > `blocks/` 文件 > 用途文件 > 语体文件 > `base.md`，因为越靠前越针对这份文档。两个例外：`easy-read.md` 的语言规则优先于其他所有文件，因为读者读不懂时其他规则都没有意义；`register/concise.md` 只放宽它列出的 `base.md` 条目。

## 4. 写

按类型文件的"必需章节"或用途文件的"结构"搭骨架，再按写作规则填内容。缺事实（版本号、参数、责任人、日期）时写 `【待补：缺什么】`，留给用户填。

## 5. 自查

逐条过第 2 步每个文件的审查清单，每条标为通过、已修或不适用（写明原因）。

**完成标准：** 每份清单的每一条都有标记。审模式下，这份逐条结果就是交付物，未通过的条目按"位置 / 问题 / 依据 / 改法"列出，依据写规则所在的文件和小节。

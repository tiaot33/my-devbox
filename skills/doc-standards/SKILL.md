# 按标准写文档

每次只处理一种文档：定类型，读两份规则文件，写，按清单自查。

## 1. 定模式和类型

模式三选一：

- **写**：从零写。
- **改写**：用户给了原稿。保留原稿的事实，改结构和文字。
- **审**：只交问题清单，不动原文。

按下表找类型文件（都在 `references/` 下）：

| 大类   | 文档类型             | 文件                   |
| ---- | ---------------- | -------------------- |
| 用户文档 | 用户手册、使用说明、安全须知   | `user-manual.md`     |
|      | 快速入门、教程、操作指南     | `tutorial.md`        |
|      | API 参考、SDK 文档    | `api-reference.md`   |
|      | README           | `readme.md`          |
| 开发过程 | 需求规格说明、PRD       | `requirements.md`    |
|      | 架构描述             | `architecture.md`    |
|      | 设计说明（模块、接口、数据）   | `design.md`          |
|      | 测试计划、测试用例说明、测试报告 | `test-docs.md`       |
|      | 文档计划、文档外包需求      | `doc-plan.md`        |
|      | 表里没有的其他开发过程文档    | `lifecycle-other.md` |
| 对外   | 通知、公告、对外说明       | `public-notice.md`   |
|      | 用户协议、隐私政策、披露文件   | `legal-terms.md`     |
|      | 科普文章             | `popular-science.md` |
|      | 易读版（给阅读困难的读者）    | `easy-read.md`       |
| 报告   | Agent 给用户的结果汇报   | `agent-report.md`    |
|      | 科技报告             | `tech-report.md`     |
|      | 学术论文、学位论文        | `thesis.md`          |


图表和仪表盘转 `dataviz`，ADR 转 `domain-modeling`。其余对不上的，问用户最接近哪一行。

一次要多份文档（如"补 README 和 API 文档"）时，按文档拆成独立任务。每份可以单独交给一个 subagent 或 workflow，只给它 `references/base.md`、对应类型文件和原始材料。

**完成标准：** 模式、类型文件、目标读者、输出语言都已确定。读者和语言没说时，从原稿和上下文推断；推断不出就问。

## 2. 读规则

先读 [references/base.md](references/base.md)：所有类型通用的语言规则。再读类型文件。两者冲突时按类型文件，因为它针对这类读者。

类型文件还不存在时，告诉用户这一类尚未收录，只按 `base.md` 写。

## 3. 写

按类型文件的"必需章节"搭骨架，再按"写作规则"填内容。缺事实（版本号、参数、责任人、日期）时写 `【待补：缺什么】`，留给用户填。

## 4. 自查

逐条过 `base.md` 和类型文件的审查清单，每条标为通过、已修或不适用（写明原因）。

**完成标准：** 两份清单的每一条都有标记。审模式下，这份逐条结果就是交付物，未通过的条目按"位置 / 问题 / 依据 / 改法"列出，依据写规则所在的文件和小节。

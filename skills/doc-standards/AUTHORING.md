# 维护说明：怎么写 references/ 下的规则文件

这份文件给维护者看，运行时不加载。`SKILL.md` 只做路由；每个 `references/<类型>.md` 独立成文，可以单独交给一个 agent 或 workflow 写、改、审。

## 文件骨架

每个类型文件都用这个骨架，标题和顺序不变：

```markdown
# <文档类型>

## 适用

- 读者：<谁读、带着什么目的读>
- 用在：<典型场景>
- 不适用：<情况> → `<其他类型>.md`

## 必需章节

1. **<章节名>**：<写什么>。
2. **<章节名>**（可选：<什么情况下加>）：<写什么>。

## 写作规则

- <一句祈使句>。

## 审查清单

- [ ] <一条能判定是或否的检查项>

## 示例

<改写前 / 改写后，各不超过 10 行。可省略。>
```

`base.md` 不写"必需章节"，其余结构相同。

## base.md 管什么

所有类型通用的语言层，类型文件不重复这些内容：

- 读者与目的：先定读者和读者要完成的事（ISO 24495-1 的相关、可找、可懂、可用）。
- 结构：结论先行、标题能概括内容、一段一个意思。
- 句子：短句、主动语态、一句一个动作、主语明确。
- 用词：常用词、一词一义、术语首次出现时解释、全文译法一致。
- 受控情态词：必须、应、可以、不得等各表示什么，借 ste-zh 的做法。
- 标点与数字：GB/T 15834、GB/T 15835。
- 版式：列表、表格、强调的用法。

类型文件只写这类文档**特有**的规则；通用规则在类型文件里有更严或不同的要求时，写明差异，如"比 `base.md` 严"。

## 写作要求

- **用自己的话概括。** ISO、IEC、IEEE 标准全文受版权保护，不贴原文，只写编号和条款号。可公开的指南（美国联邦指南、SEC Handbook、EU 指南、Inclusion Europe、Microsoft/Google 风格指南、MIT 许可的 ste-zh）可以短引，并注明出处。
- **规则文件不写来源。** 依据行、括注简称、规则后的条款号都不进 `references/`：运行时用不到，只占 token。
- **每条规则都能在来源记录里追到。** 来源统一记在 `skills/doc-standards-workspace/sources.md`，每个类型一节：依据（标准编号、版本、核对日期）、括注简称、逐条出处（规则开头 → 条款号）。只能从二手资料确认的，写"据 <来源>"；查不到来源的规则不写进规则文件。
- **版本和年份以一手来源为准。** 查不到现行版本时，在来源记录的依据里写"版本待核"。
- **规则要用到的说明留在规则文件里。** 例如"比 `base.md` 严"、（shall）（should）标记的含义、计数口径。"作者判断""本 skill 自定"这类出处说明放来源记录。
- **写 agent 默认不会做的事。** "写清楚""注意准确"这类 agent 本来就会做的话，删掉。
- **正面表述。** 写要做什么；禁止项只在无法正面表述时保留，并配上正面写法。
- **审查清单每条都能判定。** "是否清晰"不合格；"每个操作步骤只含一个动作"合格。
- **中文为主。** 英文文档另有要求时（如 Microsoft/Google 风格指南），单列一小节。
- **篇幅控制在 250 行以内。** 超出时先删重复和 agent 默认会做的内容。

## 调研笔记与来源记录

调研笔记放在 `skills/doc-standards-workspace/research/<类型>/`。增删改规则时，同步改 `skills/doc-standards-workspace/sources.md` 里对应类型的一节。整个 workspace 目录被 gitignore，来源记录不入库。
